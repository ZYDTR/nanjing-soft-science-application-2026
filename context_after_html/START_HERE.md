# 从前置HTML接续到申报书写作

本交接包与《南京创新资源研究_全文阅读_20260923.html》共同组成写作起点。它补齐HTML之后的原件核验、研究取舍、证据和制作要求。读完本页与研究设计稿，另一位写作者可独立开始A表第四、第五部分正文和公式稿；关键数学与最终MathType仍须完成，不能把“上下文连续”理解成所有研究与制作工作已经结束。

## 先识别共同任务与授权边界

申报方向为“南京市强化创新资源统筹配置的体制机制与路径优化研究”；拟题为“社会空间网络视角的南京市创新资源配置、机制设计与实现路径研究”。只写2026年A表第四部分“本项目研究的主要思想、观点和理论方法”、第五部分“研究方案（包括技术路线图）”，另交逐段创作依据README。旧A/B文件是参考，用户没有让本任务填写其他章节或B表。

用户明确决定：沿用学姐论文框架；允许主Agent提出资源边界并自行取舍研究设计；导师可协助数据库和调研，渠道较多，但实际已取得的数据不清楚。用户要求字体、字号、颜色等沿用旧A表，公式采用MathType嵌入；路线图参考学长论文。用户指定确定性子任务使用gpt-6-sol，前文已指定xhigh；核心思考和写作由主Agent承担，leaf不继续派发。

以下是主Agent的研究建议，**不是用户逐项指定，也不是已经发现的南京事实**：采用同类科技服务机构作为配置计算单元；优先围绕创新资源供需对接支持经费；公平强调合格需求与基本可达性；地区按服务受益地汇总；QCA为条件满足时的补充；拟用2021—2025年度资料。36次访谈、12组对比案例、120—180份问卷则是前置HTML提出、主Agent沿用的计划工作量，既非用户指定，也非已完成抽样。这些建议已写入当前设计稿。独立写作者可以提出更好的实现，但须保持用户约束，并解释具体改变及其证据。

原文核验优先于HTML的待核推断。两轮报告是过程快照，其中“主Agent待定”等旧状态，以本页和当前设计稿的决定为准。文献中的疑点照实保留，不因它被纳入参考文献就自动接受所有方法和结果。

## 写作所需的完整逻辑链

总体问题是创新资源在南京集聚之后，哪些主体实际能够接近、使用和转化资源，以及政府如何在可控权限内改善这一过程。先界定资源、权属与统计口径，再以地区资源结构和机构服务网络定位障碍，随后在同一可控资金池内比较公平、效率、综合三个初始方案。竞争机制研究遴选、匹配与依规调整如何影响资源实际使用；奖励机制研究绩效核验和下一轮支持规则。多维评价与案例证据共同形成分阶段政策建议。

该框架适用于提出研究计划。它尚未产生南京的最优拨款方案，也没有证明某项政策的因果效果。前置HTML的公开政策、字段规格、访问提纲和反例设计仍可使用；新增部分解决的是原框架归属、文献适用边界和研究对象的具体选择。

## 需要继续完成的数学内容

当前设计稿只锁定预算可行域与公平/效率方案组合关系，尚未完成正式ZSG推导。公式写作者须清楚区分可调经费、其他非可调投入、结果变量及其时滞；固定的是被配置资源总量，不能据此把创新成果总量设成固定。

学姐式4.12中GDP/人口名称与约束方向有歧义；式4.11年度、式5.3价格标签及式5.4意愿指标方向也有疑点。具体页码在框架证据矩阵。不得只换符号就称完成创新资源模型。科技资源ZSG直接应用论文Liu等（2021）目前只取得摘要及首页预览，完整算法未读；可继续通过合法数据库渠道补文献，也可以透明提出更合适的受约束模型。若采用后者，须说明与ZSG的关系和改造理由。

公平方案须定义合格需求、未匹配需求、服务成本及最低保障；综合权重是政策偏好，不是由熵值自动推得的社会价值。三方案须共享单位、预算和硬约束。比较历史技术下的测度和预算情景时，模拟值、预测值与真实观测分别标记；不得用自己生成的前沿和结果循环证明方案最优。

## 已有数据与拟取得数据

已核的是原始材料、公开政策、若干统计入口和已读文献。前置HTML提到的446条记录及CSV、代码、运行结果位于另一个Agent声称的配套ZIP；本任务未取得该ZIP，不能声称已回读或复现。本包不把这些记录另行冒充成数据集。

机构级申请、评审、合同、拨付、撮合、履约、验收及后续合作台账仍拟取得；数据库权限不是这些表已经到手的证明。正式写作应提出具体来源、字段、样本进入和连接方法，同时以拟开展的语气表述。长期效果主要利用已有历史记录，不承诺在12个月研究期内完成多年新追踪。

## 内容与格式的验收边界

- A表保持匿名，不出现申报单位、参加单位或团队成员身份。被研究的政策、案例单位和参考文献作者不是同一类身份信息，按必要性规范引用。
- 当前研究计划原则上12个月。调研对象、样本依据和案例资料取得路径要具体。正式申报以平台文件和现行通知为准。
- 旧A表中文正文宋体12pt，西文Times New Roman，黑色，1.5倍行距，两汉字首行缩进；一级标题黑体15pt；小节12pt加粗。第四、第五节为表外标题加单格内容表。最终按A4重排并核页。
- 技术路线为框图，另传JPG不超过400KB。当前内容图已生成PNG/JPG/SVG；最终进入Word后还需验实际版宽。图内三初配方案均置于基础配置下。
- MathType要求保持。当前本机未找到已验证的新建通道，既有Windows连接探针失败；这些只是原执行环境状态，另一写作者可使用自己的合法环境解决。最终需要新建、嵌入、修改、保存、重开验证；公式稿可以先交可读数学和可编辑源文，不能把它标为已满足MathType的DOCX。

## 怎样独立接棒

先读本页，再读设计稿和技术路线图。写框架时回框架报告和证据矩阵；写方法时看对应证据卡、必要原页及所附转换PDF；做排版时看格式规范和仓库根的旧A表。Skill用于继续提取证据，不是申报书内容模板。

写作者自行完成正文、公式论证和创作依据，不必复现全部前置调研。遇到上述真实未决事项，作出明确处理并记录依据。输出应使评审读懂研究对象、问题、方法怎样连起来，而不是复述本交接过程。README应映射第四第五部分各节及图节点到来源和研究者自创部分。

若独立写稿之间要比较优劣，建议在共同起点下评估：是否忠实于两层框架、对象与数据是否贯通、数学与制度约束是否相容、论证能否自足、计划是否可执行、证据与拟议结论是否分明。更复杂的方法清单和更多公式不自动构成更好方案。
